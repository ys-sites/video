Do · Don’t

Do

  • Put the goal in the first line: Goal: 30 s promo for X
  • Give file paths, not descriptions of files
  • Send all repo links in one message with what each is for
  • Say the stop point: brief, preview or render
  • Say “approved” or “stop” clearly — paid or deleting steps wait for it

Don’t

  • Paste a whole web article — send the link and the part you want
  • Stack five fixes in one message (it rebuilds everything)
  • Fire new requests mid-task unless they’re urgent — queue them
  • Ask for 13B video models locally — say “use cloud GPU” instead
  • Use “make it better” — name what is wrong and where
